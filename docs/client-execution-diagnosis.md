## 已核实的关键差异

2026-10-24 08:28 的完整 App 验收通过了正式的沙箱外执行通道。当时的原始调用为 `npm run test:e2e`，参数明确包含 `sandbox_permissions: "require_escalated"`；会话策略为 `on-request`。08:28:30 工具返回了实际运行的进程会话，08:33:20 返回退出码 0 和 `70 passed (4.7m)`。因此，之前的成功不能证明 Chrome 或本地监听曾经可以在受限沙箱内运行。

当前会话最近一次明确下发的策略为 `granular`、`sandbox_approval=false`，正式沙箱外执行申请被禁止。本地服务的 `listen EPERM` 与 Chrome 在页面创建前退出，发生在这一受限执行路径中。现阶段已确认的直接差异是**以前能获准执行必要的沙箱外命令，现在该授权通道不可用**。

用户界面显示 `On request` 与实际执行策略不一致。尚未取得足以区分会话绑定、设置传递、服务端策略覆盖等原因的证据；不能声称已找到具体的设置同步缺陷。

## 本轮新增的实际失败证据

通过正式客户端接口分别调用 `check_app_update` 和 `list_threads`，两次均返回 `Codex app tool request failed`。客户端日志在 10 月 25 日 20:24:29 和 20:28:03 记录了对应的：

```text
dynamic_app_tools_request_failed
The app tool call ended before producing a result
```

源代码显示该错误由应用工具回调返回空结果触发；窗口不接受调用和调用中途结束均可能落入相关路径。源码中对 ChatGPT 来源的限制是可核对的候选解释，日志未记录本次请求的完整路由参数，因此不把它认定为所有权限问题的同一个根因。

本地执行器的连接观察持续正常，应用工具通道的 socket 文件存在。检查到的用户和项目配置中没有覆盖审批策略的设置；检查的 `/etc/codex/` 与常见 macOS managed-preferences 文件不存在。此检查不排除云端或其他托管策略。

正式更新查询失败，不能确认当前版本已是最新或已有修复版本。未安装、降级或重启客户端，未修改客户端包、系统策略或用户权限。
