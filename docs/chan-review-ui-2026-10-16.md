## 已确认的问题

### 1. [P2] 最小矩形高度改变了真实低价位置，虚线跟随错误边界

位置：`src/components/ChanFractalDetail.jsx:125–126` 与 `:158–164`。

合并图把区间矩形高度设为 `Math.max(1.5, y(low) - y(high))`，而低价虚线读取该矩形的 `getBoundingClientRect().bottom`。当真实高低区间不足1.5像素时，矩形底部不再是 `y(low)`，虚线会与原K真实低点错开；tooltip 与 `data-price` 仍写真实 low，图形表达与数据不一致。普通宽区间测试只能验证虚线跟随矩形，无法发现这个问题。

独立复现输入，按时间列出 `[high, low]`：

```js
[[99, 1], [100, 99.998], [100.001, 99.997], [99.5, 90]]
```

每根原K取 `open = low + (high-low)/3`、`close = high - (high-low)/3`，因此所有 OHLC 均在合法范围内。按当前引擎，中间两根向上包含合并，结果 `[low=99.998, high=100.001]`，四项顶分型条件全部成立。高与低来源分别是第三、第二根原K。

1280×900实际浏览器测量：

| 对象 | 页面 Y 坐标 |
| --- | ---: |
| 高价100.001真实源影线顶部 | 400.967743 |
| 高价虚线 | 400.967743 |
| 低价99.998真实源影线底部 | 400.972534 |
| 低价虚线 / 被撑高后的矩形底部 | 402.467743 |

低价误差为 **1.495209 CSS 像素**。这是确定的几何偏差，不是浮点格式化误差。

修复方向：区间的两个语义边界必须保留精确 `y(high)` 与 `y(low)`。如需最小可见厚度，应以独立装饰表达，不能拿被撑高后的装饰边界作为真实价格锚点；虚线应核对实际源影线相应端点与真实结果边界，而不只核对画出的矩形。

### 2. [P2] 手机外层三图滚动裁切未计入虚线源点可见性

位置：`src/components/ChanFractalDetail.jsx:144–161`、`:176`，外层滚动容器在 `:250`。

`MergeGuides` 只检查源点是否处于原K图自己的滚动容器矩形内，没有与外层三图滚动容器的可见区域求交集。外层裁掉源点后，该虚线仍显示为从视窗边缘延伸到结果K，用户无法看到真实来源。此外，监听器加在 `comparison` 上，捕获不到其父滚动容器自身的 scroll 事件；若补充外层可见性判定，也必须补上该父容器的更新触发。

独立复现输入 `[high, low]`：

```js
[[7, 3], [8, 4], [8.5, 3.5], [10, 6], [9, 5]]
```

使用与上例相同的合法 O/C 构造。详情实际原K为后四根；左组的第二、第三根原K向上合并为 `[4, 8.5]`。在 **320×844** 手机视口，将外层三图容器滚到最右：

| 对象 | X 可见范围 / 位置 |
| --- | ---: |
| 外层实际可见区 | 13 → 307 |
| 原K图自身 DOM 范围 | -58.34375 → 112.328125 |
| 低价4的真实源影线 | **-21.34375**，已在视窗外 |
| 结果K低价边界的左端 | 152.744797，可见 |

仍存在 `data-chan-detail-guide="0:low"`，线的真实起点为 -21.34375，但显示部分从外层裁切边缘开始。高价8.5的另一来源 X=18.65625，仍可见，两条线需要分别判断，不能整组共用一个可见状态。

另测390px初始位置：结果K整体在外层右侧不可见，仍绘制两条通往画面外结果的虚线。建议根据期望交互明确要求两端均可见，并对原图、结果图、外层容器与视口作相应裁切求交，不能只检查内层原图。

## 数据接线中需要明确的阶段差异

以下为初审计数；主任务在引擎修复后又按当前生产入口复跑，仍为相同数量（1601个标记、89处快照差异、26处类别差异、10处涉及最新输入K）。按13个保存行情夹具的实际周期调用 `analyzeChan`，独立遍历 **1601个可点击标记**：

- 1601个标记均能取到对应 kind/time 详情；几何四条件均成立。
- 未发现标记 mark/price 与详情不符、分型锚点原K的对应 high/low 不等于 price、来源数量不等于 `to-from+1` 的情形。
- 同一个 time 的 fx 与 bi，存在 **89处三K来源/区间快照不同**，其中 **26处直接 / 包含类别不同**。这些数字按夹具周期运行；全部强制默认 day 的另一统计口径得到84处，不应混写。

例：`hk00700-5m.json`，time=176，底分型 price=425.6：

| kind | 原K数 | 左 / 中 / 右合并来源范围 | 右K高低 | UI类别 |
| --- | ---: | --- | --- | --- |
| fx 圆点 | 3 | 174 / 175 / 176 | high=427.6, low=425.8 | 直接底分型 |
| bi 三角 | 4 | 174 / 175 / 176–177 | high=427.6, low=427 | 包含关系的底分型 |

这是现有增量引擎分别保留不同阶段快照的实际结果，不是 `Chart` 读错 kind：主图确实按 `fractalDetails.fx` / `.bi` 分开读取。保持独立快照可避免后一阶段覆盖此前计算，但当前详情标题与类别结论未说明阶段差异，同一个主图低点因此可能呈现两种类别。不能对用户声称“圆点、三角详情完全相同”或“当前完整行情只有一套完全一致的分型来源”。是否应统一为当前快照，或在原有 tooltip 中说明计算阶段，需要与引擎规范一起决定；本轮没有擅自覆盖快照。

## 其他核查结果与边界

- **原始 OHLC / 合并区间**：原图影线来自真实 high/low、实体来自真实 open/close；右图矩形几何只读取合并 high/low，没有构造伪开收盘。第一项最小高度问题除外。
- **颜色**：右图按来源组首根 open 到末根 close 的变化着红绿，这是应用辅助编码，不是62/65课的分型或包含定义。改变 O/C 会改变颜色，不会改变合并高低几何与条件。既有文档说明了该约定，当前右图 tooltip 只有高低与来源编号，没有向用户解释颜色约定；不能把红绿解释成合并矩形上下沿是开收盘。
- **标准示意图**：顶侧上边界 `[128,56,92]`、下边界 `[218,146,182]`，中柱高低都高于左右；底侧上边界 `[92,128,56]`、下边界 `[182,218,146]`，中柱高低都低于左右。两者几何均成立。右侧高于左侧只是选定的一种有效示意，不是顶底分型额外条件。示意标有“形态示意”，没有参与真实价格尺度。
- **日期与序号**：详情原K编号1…N为本次详情的相对编号，右图来源编号同样相对 `detail.rawCandles` 查找，未把引擎局部 `idx` 误当显示编号。原日期字符串直接保留在 tooltip，组件没有时区转换。`analyzeChan` 截断历史后 time 仍为过滤后全历史序号，而来源 idx 为引擎输入局部下标；目前各自用途没有交叉。手机浏览器原生 SVG title 的可发现性不是本轮保证事项。
- **滚动与几何**：普通宽区间样例的高、低分别来自不同原K，桌面与390px手机实测与源影线端点差值为0；127根长包含在原图滚到开头时不绘制右端离屏来源，滚到末尾恢复两条正确端点。第一、二项反例说明这不等于所有布局和区间均正确。
- **笔与确认**：图例仍写“三角：笔端参考 · 实线末端：动态极值”，详情没有“已收盘确认”“确定反转”“已完成上涨/下跌”等明确文案。特征说明写明只看三K、还需后续走势验证。数据本身没有收盘状态，1601个标记中10个详情使用最新一根输入K，不能额外声称这些点都经过收盘确认。当前几何展示不等于已验证未来成笔或反转。
- **事件与资源**：详情继续通过 body portal 与主图原生 wheel 监听隔离，并阻止 React mouse/touch/pointer 冒泡；`MergeGuides` 的内层 scroll / window resize / ResizeObserver / rAF 均有卸载清理。未发现新增残留监听路径。

## 本轮后续修复与独立回归

审查后获准仅修复 `ComparisonChart` / `MergeGuides` 两处已证实的 UI 根因；没有修改标题、结论或特征规则。

- 合并区间矩形取消1.5px最小高度，真实高低同价时保留零高区间，并额外绘制同价水平线，避免伪造非零价格区间。
- 虚线从原K影线真实 SVG 端点及结果区间真实 SVG 价格坐标经 `getScreenCTM()` 换算，既不读取被撑高的矩形，也不移动源点去匹配其他K。
- 源、目标分别与各自内层滚动区域、外层三图滚动区域、dialog 裁切及浏览器视口求交；任一连接端点不可见时不画该条线。
- 捕获滚动改为 window capture，以接收外层祖先容器滚动；尺寸观察覆盖裁切祖先。rAF、监听和 ResizeObserver 仍在卸载时清理。
- 原生 modal 属于 top layer，求裁切交集时止于 dialog，不错误应用 body 的背景锁滚动裁切。

新增独立脚本 `scripts/checkChanGuideGeometry.mjs`，使用单独的临时 Vite cache，不修改原有浏览器脚本。已实际运行：

```sh
node scripts/checkChanGuideGeometry.mjs
```

**11个独立浏览器场景通过**：普通不同来源高低、极窄区间、H=L零区间、390px结果离屏/恢复/滚回、320px源点被外层裁切、resize后恢复、127根内层滚动隐藏/恢复、深色显示。各条已显示虚线都同时与真实源价及结果价对齐；极窄区间高度保持小于0.01px。Escape 关闭后 window scroll capture 与 ResizeObserver 活跃计数均回到0，背景滚动锁恢复，成功轮无 pageerror。
