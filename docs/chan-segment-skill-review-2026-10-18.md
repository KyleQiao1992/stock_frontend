## 已修复反例

### 首笔破坏等低/等高

独立、全部明确已确认的笔端价格为 `[0,10,4,12,4,8,3]`。前三笔成立，第一反向笔12到4破坏旧段，后续第三笔8到3又跌破第一笔结束位置4。原实现要求 `center.low < left.low`，两者同为4而漏入首笔破坏分支；普通分型条件又不能接受等低，导致始终无确认段。

将这一分支改为 `<=`，向下镜像使用 `>=`。回归覆盖最小例、延长例 `[0,10,4,12,4,8,4,7,3]` 及上下镜像。此修复没有把所有分型的比较一律放宽成非严格比较。

### 未收盘K参与确认

原合成行情第66根K即使显式标为 `complete:false`，仍会生成确认段；保持同一K，只扩展其高点又会撤销。这不是已收盘逐根追加测试能排除的问题。

现按所有原始必要证据的完成状态确定笔端是否可供线段确认：

- `complete:true`：允许以该K作为完成证据。
- `complete:false`：不能确认，不因后来有K就擅自覆盖来源的明确标识。
- 来源未给状态：最新K保持候选；观察到后继同周期K后，才认为前K已完成，依据时刻记录为后继K。

没有按本机日期猜测市场收盘，也没有冻结已被上游笔撤回的线段。合成闭合行情的测试显式设置 `complete:true`，保存网站样本不伪造该字段。

## 回放与历史窗口

`npm run audit:chan-segments` 可重跑13组保存行情的4787个前缀。报告在[因果回放JSON](./chan-segment-causal-audit-results.json)：固定起点范围内，新出现或撤销后重新出现的段，其依据K与当时可知的输入一致；持续存在的段没有无故时刻漂移。

这些保存样本没有超过各自请求窗口上限，不能据此声称滚窗边界已验证。同一审计脚本另外用显式收盘的合成输入重现300日K窗口移动：窗口改变可新产生历史段，其必要证据位于过去，但段是新窗口下才出现。原文第78课允许选择起点，也指出起点会影响大走势认识。

因此界面明确写“确认依据K（本次历史窗口复算）”，不再把它说成系统跨请求的首次观测时刻；面板展示线段历史起点。当前没有历次盘中快照/信号事件存档，不能把这些事后重建的段直接作为无未来数据的交易回测信号。
