## 2. 核心判断

这套设计较突出的地方，是把分析组织成连续的阅读流程：

**综合结论 → 多周期背景 → 图上结构与信号 → 辅助指标 → 后续条件与复盘。**

它让用户先知道当前应关注什么，再找到对应的图上依据。截图能支持“分析呈现有章法”的判断，但不足以证明算法更准确、信号更及时、收益更高或产品整体优于本项目。

## 4. 最值得借鉴的设计

### 4.1 多周期摘要要能解释差异

移动截图同时呈现周线“上涨趋势”、日线“下跌趋势”、4 小时“下跌趋势”，并给出各自的结构状态。这种并排呈现有助于区分长期背景和短期变化。

本项目建议：每个卡片显示周期、数据截至时间、趋势、结构位置和最近信号；点击卡片切换主图。综合结论需要明确其适用周期和依据，避免顶部“上行衰竭”与下方不同周期状态之间产生理解歧义。

### 4.2 结论应有可以定位的图上证据

笔、中枢、背驰和买卖点放在同一张图上，用户可以把术语与具体行情对应起来。

本项目建议：点击分析文字或信号后，定位并高亮相关 K 线、笔、中枢和指标区间；同时解释采用的规则、当前状态和失效条件。不能只增加标签数量。

### 4.3 情景路径要配条件

截图的条件推演通过多条路径表达不同可能，并明确提示不是预测。这是有辨识度的呈现方式。

本项目建议：每条路径必须给出触发条件、关键结构或价格、确认条件和失效条件；如果只是示意，明确说明横向长度与纵向幅度不代表预计时间或目标价。没有验证依据时，不添加成功概率。

### 4.4 未确认状态应一致表达

截图用虚线提示未确认结构，这有助于解释为什么末端结构会变化。

本项目建议：统一处理中枢、笔、线段、信号和推演的状态语义。颜色、线型和文字共同表达，不能仅依赖颜色。保留“候选出现”和“正式确认”的区别。

## 5. 不能从截图得出的结论

- 有“一买”标签，不等于能够在该根 K 线结束时实时确认。必须核对首次可知时间与确认时间。
- 有回放入口，不等于有策略回测。回测还需要交易规则、成交约束、手续费、滑点和完整交易记录。
- 有推演曲线，不等于有经验证的预测能力，也不能据此赋予路径概率。
- 有“雷达”“基本面研究”等入口，不等于其后台与页面已经完整可用。
- 图形整齐，不等于缠论口径正确。笔、线段、中枢、趋势与背驰需要分别核对定义及边界样本。
- 历史图上存在信号，不等于当时可以看到该信号。复盘必须排查未来数据参与计算和事后补画。

## 9. 线段与中枢为何可能与教材观感不同（2026-10-23 追加）

触发：用户反馈线段、中枢定义看起来不自然，与教材图有差距。本次先审查当前工作区实际代码和保存行情，不根据外观直接更换算法。用户尚未指定某本教材的具体图例，因此没有完成同一原图的逐端点裁决。

### 9.1 已确认的结构口径差异

当前 `src/lib/chan/index.js` 实际执行两条独立计算路径：

- `buildSegments(segmentBi)`：从明确确认的连续笔端构造特征序列线段。
- `buildZs(bi)`：调用 `referenceZs.js`，直接从笔构造滑动重叠区；不使用上一步的线段结果。

因此，当前图上的紫色线段与彩色框没有“由这些线段构造这些中枢”的依赖关系。界面开关已称“重叠区”，图例也说明“非递归中枢”，但这仍然不能满足把色框当作同级走势中枢来读图的预期。

`referenceZs.js` 的具体行为及影响：

| 实际规则 | 可能造成的观感 |
| --- | --- |
| 每个笔起点独立检查连续三笔交集 | 同一震荡范围内出现多个互相交叠的候选框 |
| 每个候选最多包含九笔 | 持续重叠也会被窗口截断；没有在此执行级别升级 |
| 只按候选的笔索引范围去除被包含项 | 框在价格、时间上高度交叠时，仍可能同时保留 |
| 输入不筛选 `confirmed === true`，末笔端可以参与 | 色框的结构状态与实线确认段不同，尾框可能随笔链变化 |
| 没有严格走势中枢的延伸、离开、回试及递归生命周期 | 不能用框的数量直接推导同级趋势或三类买卖点 |

这不是说“三笔重叠”不能作为辅助分析，而是其对象和级别必须与走势中枢区分。原作者[第 17 课](https://blog.sina.com.cn/s/blog_486e105c010007p1.html)从连续次级别走势类型定义中枢，并说明最低不可再分级别的处理；[第 20 课](https://blog.sina.com.cn/s/blog_486e105c010007zw.html)进一步区分中枢延伸、新生与级别扩张。不能把每三笔的滑窗框无条件等同于这些定义，也不能把“最多九笔”本身当成扩张算法。

### 9.3 对线段本身的判断

当前线段实现确实使用反向笔特征序列、包含处理、分型和缺口分支，与[第 67 课](https://blog.sina.com.cn/s/blog_486e105c01000c16.html)讨论的是同类结构，不是简单连接局部高低点。还需区分以下情况：

1. **确认时间差异**：当前笔端成为后继合法反向笔的起点、且必要 K 线完成后，才参与线段确认。已确认线段少、确认滞后，不足以单独证明漏段；需要与教材的完整历史图、当时可知状态分别比较。
2. **复杂段可能外观不直观**：[第 78 课](https://blog.sina.com.cn/s/blog_486e105c01000cio.html)明确讨论笔破坏未发展为线段破坏、旧段继续延伸，以及段起点未必是内部最高点的情况。不能为了折线更整齐而强制按视觉拐点切段。
3. **上游口径影响下游**：当前笔采用包含处理后的独立 K 条件，`MIN_BI_LENGTH=7`；教材若采用不同笔口径、行情起点或数据，线段结果也会不同。
4. **尚有需裁决边界**：前三笔仅点接触是否成立、候选恢复时触及旧端点是否应与突破等价，以及复杂特殊结构，不能仅凭既有单测宣称全面符合原著。前次复核中的未决边界仍见 [线段技能复核报告](./chan-segment-skill-review-2026-10-18.md)。

本次重新打开作者第 17、20、67、78、81 课正文。第 81 课包含对第 71 课末图的更正，后续选教材图例时应核对更正版本。本次未完成全部原图的视觉复核。

### 9.4 下一步对照标准与实际验证范围

优先以一个明确的教材图例固定以下条件：同一行情、周期、复权方式、历史起点、笔定义，以及图例属于完成后的历史划分还是当时的候选结构。然后依次核对分型、笔、段、构枢单位、延伸/离开/扩张，记录首次分歧，避免一次性更换多个算法后无法归因。

如果目标是教材中的走势中枢，应先统一构枢对象与级别；“笔重叠区”和明确约定的最低级别线段结构可以分别作为辅助层，但不能共用同一个含义模糊的“中枢”标签。更高层级仍需走势类型递归，不能只把 `bi` 换成 `segments` 就宣称完成原著实现。
