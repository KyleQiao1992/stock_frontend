## 2. 分型与包含：公式符合，输出语义需要补全

### 已核对的规则

- 对相邻包含K按时间顺序处理，后一个输入与已经合并的结果比较。
- 向上合并取较高高点、较高低点；向下取较低高点、较低低点。
- 顶分型的中间处理K，高点和低点都高于左右处理K；底分型相反。
- 使用高低点，不用实体颜色或收盘价代替；没有额外要求第三K必须突破第一K的另一侧。
- 有明确前趋势时，代码用前两根非包含K确定合并方向。这与第62、65课核对的核心规则相符。

### 已复现的输出差异

1. 原始区间 `[高,低] = [[8,4],[10,6],[9,5]]`，第三根显式 `complete:false` 时，当前输出仍有第二根的顶分型 `{time:2, price:10, mark:'G', idx:1}`，不携带 `confirmed` 或确认时刻字段。它是盘中可变化的几何候选，不能当作已收盘确认。代码没有把它显式写成不可撤销信号，但输出层不足以独立辨别两者。
2. 七根无包含K `[[3,2],[2,1],[3,2],[4,3],[5,4],[6,5],[5,4]]` 产生K2底、K6顶两个笔端；分型圆点输出只保留K6，省略首笔锚点K2。圆点列表不是全量分型目录，不能根据圆点少一个就判定几何扫描漏检。
3. 当前圆点还可包含尚不足以组成一笔的局部三K转折。几何候选、经笔规则筛选的端点及原文结合律语境需要区分，不能将所有局部圆点都解释为最终可连接分型。

### 实现约定

开头缺少方向的包含前缀被跳过；合并等极值取较右原始K定位。这些是当前工程约定，未证明为作者唯一规定。起点不同、原始数据与处理后K混看，也会造成图像差异。

## 3. 笔：当前采用旧笔，不能与新笔图直接比较

### 已核对的旧笔条件

当前要求异性质顶底、价格方向正确、两个完整三K分型之间至少一根处理后独立K，并以 `MIN_BI_LENGTH=7` 限制最小结构。原始包含K不能充当独立处理K。六根不成立、七根成立及上下镜像等现有用例通过。

同性质初始锚点取更极端者；等价保留较早者。笔链会随尾部证据变化回退，最后端点标为未确认。确认状态用于线段输入；它不是系统跨请求保存的首次观测日志。

### 与作者新笔补充的差别

2007-09-18课外补充放宽了独立处理K要求，仍禁止两端分型共用处理K，同时按原始K数量检查两端极值K之间的间隔。

例如原始区间：

```text
[高,低]：[[3,2],[2,1],[3,2],[3,2],[4,3],[5,4],[4,3]]
```

中间重复区间合并后只有六根处理K，两端分型不共用处理K，但没有额外独立处理K；原始底极值K2与顶极值K6之间有三根原始K。按补充文的这两项计数条件可通过，而当前旧笔不成笔。这里的新笔判断为按来源手工核对，不是项目已有新笔引擎的输出。

这属于版本差异，不能将“未实现新笔”直接写成“旧笔必然错误”；但也不能宣称实现了作者全部后续修订。

作者要求顶分型的最高K区间有部分高于底分型的最低K区间。当前活跃引擎采用价格方向检查加“双向严格包含排除”，没有把必要条件直接写成 `top.high > bottom.high`；保留的非活跃 `bi.js` 则有这个直接检查。

## 4. 线段：已确认包含合并后的缺口分支失效

### 原文规则和当前缺陷

第67课先对特征序列包含标准化，再按标准序列前三元素识别分型和缺口。有缺口情形还要等待反向特征序列分型；不能直接用无缺口条件确认。第71课明确转折点后的同性质元素可以进行包含处理。

`segment.js → boundaryProof()` 在 `appendFeature` 合并之前计算：

```js
const gap = !overlaps(left, center);
```

随后 `middle` 可能因包含合并而改变区间，但确认分支仍读取旧的 `gap`。因此，最初重叠、合并后分离的场景会误走 `feature_no_gap`。

### 手工可核对的反例

给定明确确认、交替方向的笔端价：

```text
0 → 100 → 40 → 120 → 50 → 115 → 110 → 114 → 105
```

考察从0向上、候选在120结束的线段，向下笔的特征区间如下。所有区间按 `[低,高]` 书写：

| 元素 | 笔 | 区间 |
| --- | --- | --- |
| X1 | 100→40 | [40,100] |
| X2 | 120→50 | [50,120] |
| X3 | 115→110 | [110,115] |
| X4 | 114→105 | [105,114] |

X3包含于X2，按向上方向取高高，合并为 `[110,120]`。标准化后前三元素为：

```text
[40,100]， [110,120]， [105,114]
```

这是一个顶分型，且第一、第二元素之间有 `(100,110)` 缺口。此时反向特征序列只有向上笔 `50→115`、`110→114`，还没有底分型，不能按无缺口分支确认原段结束。

**实际结果：** 当前代码输出0→120已确认线段，`feature_gap:false`、`confirmation:'feature_no_gap'`。价格上下镜像也复现相同错误。

### 完整计算入口复现

为排除只向底层函数传入不可能笔端的情况，另外构造有效OHLC：

- 转折价 `[20,0,100,40,120,50,115,110,114,105,113,104,112]`。
- 每两个转折之间线性生成8根K；价格整体平移200，高低分别加减0.1，开收相同，成交量100；明确 `complete:true`。
- 使用前82根，调用真实 `analyzeChan(rows, 'day')`。

实际产生的确认笔链能到达该缺口情形，输出 `segment-9-33`，在K82以 `feature_no_gap` 确认。上下镜像均失败。此为合成行情的算法反例，不代表真实本地行情或浏览器页面已经验收。

### 其他线段结论

基本特征序列方向、前三笔重叠、奇数笔、常规无缺口、有缺口的反向分型、第二序列不强制补缺口等已有实现和用例。但这个新反例已经足以否定“当前线段全部严格符合原著”的结论。

前三笔仅点接触、候选回到旧端点时“触及”与“突破”的区别、复杂段完整案例仍需裁决。旧有第71/81课数值案例属于结构等价构造，不是所有原图的像素和行情复核。
