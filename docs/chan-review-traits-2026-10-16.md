# 顶底分型形态分类独立审查

日期：2026-10-16。范围：`topFractalTraits.js`、`bottomFractalTraits.js`、两者既有单测及详情快照调用链。本次没有修改主图标记、UI、分型/笔/中枢引擎或既有测试。本文不是整个108课及引擎的无条件正确性证明。

## 原始依据与软件约定

实际读取了作者新浪博客[第82课：分型结构的心理因素](https://blog.sina.com.cn/s/blog_486e105c01000cq4.html)的完整课程文字。该课分别讨论了中继、力度和第三K跌破第一K低点的形态，并要求结合后续及小级别走势。原文中继描述使用“小阴、小阳”；本次采用阴阳实体必须非零的严格解释，不把精确十字混入该条件。底分型按原文的反向处理说明检查对称性。

该课未为这些形态给出60%、50%的判定数字。当前实体/本K振幅60%、后两实体/首实体50%、影线/振幅50%均为软件占比规则，不足以证明历史或绝对长度意义上的长K。本次保留既有比例，没有凭空补一个新的绝对长度阈值。

## 已复现并修复

以下数组按 `(open, high, low, close)` 排列；底案例为以30反射的对应价格。

| 问题 | 最小反例与修复前实际行为 | 本次修复 |
| --- | --- | --- |
| 把精确十字作为中继的小阴阳 | `(10.5,20,10,19.5)`、`(20,22,12,20)`、`(18,21,11,18)`：后两实体均为0，仍命中`continuation`。 | 后两实体须分别大于0且满足原有小实体比例；顶底都增加第二、第三根单独及同时为十字的反例。 |
| 无效OHLC被当作有效形态 | `(11,15,10,14)`、`(25,20,12,13)`、`(13,17,11,14)`：中K开盘25超过最高20，经过实际`analyzeChan`仍得到几何有效快照及`strong`。 | 分类前逐根要求OHLC有限且`low <= open/close <= high`，否则返回`applicable:false, reason:'invalid-ohlc'`；不钳制、不替换原始价格。 |
| 缺失开盘被误当没有阳线恢复 | 删除上例正常三K中第三根的`open`：阳线比较变成false，否定表达式随即变成true，可误报`strong`。 | 相同完整性检查阻止此误判。正常`analyzeChan`先过滤非有限输入，故此缺值案例直接证明的是导出分类函数缺口，不冒称正常页面已发生此错误。有限但不可能的OHLC则已复现完整快照链路。 |
| 软件展示优先级被说成真实强弱排序 | `(10.5,20,10,19.5)`、`(20,22,12,21)`、`(11,21,9,12)`：同时命中中继与相对高点，说明却称优先展示更强特征。 | 保留全部`matches`和现有主标签顺序，改为“按展示规则优先显示”，不以软件排序证明三类的必然强弱。 |

另复现了高实体占比不等于绝对长K：首根`(200,200.03,200,200.03)`仅有0.03实体，后两根`(200.18,200.2,200.04,200.19)`与`(200.1,200.18,200.02,200.11)`各有约0.16振幅，现比例规则仍命中中继候选。由于第82课没有给出绝对长度数字，不能把此例伪装成存在唯一数字答案的原典公式错误。本次在说明中准确改称软件实体/影线占比候选，并明确不能据此证实绝对长K；未把候选改称原典已确认结论。

## 保留的逻辑及边界

- 第82课强顶条件中，关于第三K的字面否定可以写为`!(阳线 && 收盘高于中间K区间中点)`。因此第三K是阴线或十字、但收盘仍在中点以上时，现规则仍可命中强顶；底按阴线与中点下方对称。此次保留该字面解释及既有反例，没有把它悄悄改为只看收盘位置。阴阳条件缺少OHLC时则拒绝分类。
- 相对高点/低点的数字比较及标签保留为三K形态特征，说明仍明确未使用后续行情、需要后续验证；不把它当成真实高低点已经确定、后续已经成笔或确定买卖点。
- 包含后的高低区间没有真实合并OHLC，现功能继续不为其强套阴阳实体分类。第82课对直接阴线吞阳的包含情况另有讨论；当前`inclusion`排除是本功能的覆盖边界，不应宣称已经完整实现该例外。
- OHLC完整性与几何分型条件是不同问题。反例中原始`isValid`仍仅反映高低比较，本次分类返回`invalid-ohlc`；UI对此状态的显式显示由根任务负责，本次未检查其最终页面效果。
