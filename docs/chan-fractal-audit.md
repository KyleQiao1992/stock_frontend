# 第一轮验证：顶底分型与 K 线包含处理

核查日期：2026-10-15。核查的是当前本地生产代码路径，不是线上部署验收。

**复核结论：当前实现先处理包含关系、在处理后的 K 线上判分型，再把极值映射回普通 K 线图。这条计算与显示路径正确，已知前趋势下的基本判定和包含公式通过本轮核验。但起始方向不明时仍存在不对称，不能宣布整个实现无条件完全正确。**

**纠正之前的判断：旧版审计把3项“没有画出全部局部分型圆点”计为定义失败，前提不足。** 主图沿用笔引擎筛选输出；全量几何分型与筛选输出不同是事实，但没有确立“必须画出全部分型”的显示要求，不能凭这3项差异判算法错误，也不能把它们都解释成 K 线合并。这次保留差异数据、修正验收归类，没有用修改生产逻辑来使测试通过。

本轮未修改分型判定、包含合并、笔、中枢或主图绘制行为。唯一的生产代码变动是从 `referenceEngine.js` 导出其原有两个纯函数，供测试直接调用；未接入另一个替代实现，也没有部署。

## 依据与验收定义

已经直接核查作者新浪博客正文：

- [第62课：分型、笔与线段](https://blog.sina.com.cn/s/blog_486e105c01000bf2.html)，2007-06-30：三根 K 的高、低同时比较；包含按方向合并；忽略阴阳颜色，仅看高低区间。
- [第65课：再说说分型、笔、线段](https://blog.sina.com.cn/s/blog_486e105c01000bpo.html)，2007-07-16：顺序处理包含；方向依据先前非包含关系确定，不能先假定未来顶底再反推合并方向。
- [第82课：分型结构的心理因素](https://blog.sina.com.cn/s/blog_486e105c01000cq4.html)，2007-09-24：另讨论影线、实体、第三根收盘位置及力度。力度与几何成立是不同问题。
- [CZSC v0.9.69 `analyze.py`](https://github.com/waditu/czsc/blob/v0.9.69/czsc/analyze.py)：已核对当前移植所用的包含、分型、首笔锚点和 `fx_list` 汇总逻辑。它证明实现约定的来源，不作为缠论原典的替代。

令处理后的三根 K 为左、中、右，最高价 H、最低价 L：

| 项目 | 本轮验收条件 |
| --- | --- |
| 顶分型 | `H中 > H左` 且 `H中 > H右`，同时 `L中 > L左` 且 `L中 > L右` |
| 底分型 | `L中 < L左` 且 `L中 < L右`，同时 `H中 < H左` 且 `H中 < H右` |
| 相邻包含 | 一个完整高低区间落在另一个内；按闭区间理解，包括相等边界 |
| 向上合并 | `H=max(H1,H2)`，`L=max(L1,L2)` |
| 向下合并 | `H=min(H1,H2)`，`L=min(L1,L2)` |
| 连续包含 | 从左到右，每次用已经合并出的新 K 与下一根比较，不能用包含的传递性一次分组 |
| 方向来源 | 合并对之前的一对非包含 K 的方向；开头缺历史时属于额外初始化问题 |
| 分型时间 | 中间合并 K 的实际极值所在原 K；不要误称第三根的时间是极值时间 |
| 成立与突破 | 第三根不必跌破／升破第一根的另一端，就可以成立普通顶／底分型 |

严格比较是根据包含处理后相邻非包含区间推导出的表达；同价极值具体取第一次还是最后一次，不冒称原文指定唯一的软件定位规则。

用户图片中的“向上取高高、向下取低低”符合上述规则。“向右合并”如指按时间顺序处理，也与顺序原则一致；如指先定位局部极值，再仅合并其右侧，不能替代全序列包含处理。“个人认为自然 K 线无需合并”及“只合并顶底附近”不作为原典标准。“突破 K／突破参考 K”也不追加为普通分型的必要条件。

## 已确认的问题与限制

### 1. 主图分型输出不是完整的局部几何分型列表

以下每项为 `[最高价, 最低价]`，时间用第几根表示，全部相邻无包含，不涉及初始化争议：

```text
K序号  1    2    3    4    5    6
最高   3    2    3    4    5    4
最低   2    1    2    3    4    3
```

定义期望：第2根是底分型，价格1；第5根是顶分型，价格5。

主图实际：`fx` 只有第5根的顶；`bi` 同时包含第2根底和第5根顶。前三根输入时底分型原本存在，六根输入形成笔后，该底从 `fx` 消失。

原因在 `referenceEngine.js` 的 `strokes.flatMap((s) => s.fx.slice(1))`，聚合时删除每笔列表首项；第一笔的起始锚点因此未进入圆点输出。其上下镜像同样漏掉首个顶。

这一步发生在笔已经计算完毕以后，`bi` 单独从笔对象的起止点生成。因此**这一圆点汇总步骤不改变已算出的笔**，新增两组主图入口测试也核实了起始端点及笔线都仍在。这个结论不能推广为所有锚点筛选都与笔无关。

另一个更短的未成笔例：

```text
[高,低]： [2,1] → [4,3] → [3,2] → [5,4] → [4,3]
定义期望：顶@2(4)、底@3(2)、顶@4(5)
主图 fx：顶@4(5)
```

原因是首笔起点先选同类更极端的锚点，再从该锚点前一根截取待分析区间，较早的两个局部有效分型被移除。**这属于计算首笔的起点选择，确实参与后续笔计算，不能叫作纯显示过滤。** 本轮确认它与所移植 CZSC 的初始化逻辑相同，不据此宣称该首笔政策已通过所有严格成笔条件的验证。

上述行为来自当前移植的 CZSC 笔引擎约定；现有13组网站样本也保持一致。可以将其称为筛选后的分型，不能称为全部局部几何分型。这些差异与是否合并 K 线是两个问题；以上两个示例的相邻 K 线均无包含。

### 2. 起始处没有明确方向时，包含处理存在不对称

```text
原序列：[1,0] → [2,0] → [2,1] → [1,0]
实际：顶@3，价格2

围绕10作上下镜像：[10,9] → [10,8] → [9,8] → [10,9]
实际：空列表（没有与原顶对应的底@3，价格8）
```

起始两根直接压入；前两根等高时 `mergeNext` 直接返回原始 K。没有前方非包含关系时，原典方向前提尚不具备，不能把这种状态默认当成已完成标准包含处理。这里未发现有明确前趋势之后的同类公式错误；两种情形不能混为一谈。

本次另检查了13组网站基准输入的首对 K，均为非包含。因此这些样本的通过没有覆盖上述起始边界；也不能用这个人工反例推断603818当前截图中的某个分型一定画错。

### 3. 实时右 K 的收盘确认没有单独建模

```text
[2,1] → [3,2] → [2.5,1.5]：出现顶@2
同一右 K 更新为 [3.5,1.5]：顶消失
```

三根快照符合时引擎即输出，当前 `fx` 不含 `confirmed`、`confirmedAt` 或右 K 已收盘状态。未收盘 K 变化导致形态消失本身是正常现象，不能据此认定公式错误；但也不能把该快照输出称为已收盘、不可撤销的确认。本轮未连接线上实时报价验证收盘时序；不将动态笔的 `pending` 冒充为分型确认状态。

### 4. 当前主图没有实现分型力度分类

当前输出主要为 `time / price / mark / idx`，没有强／弱分类。第82课的力度还涉及实体、影线、收盘位置与小级别结构，不能把基本成立测试通过当作力度验证通过。

### 5. 等价极值定位是实现约定

生产引擎向上合并同高、向下合并同低时保留较右原 K；旧 `fractal.js` 保留较早原 K。二者不应混在一个测试口径里。这不改变分型极值价格，但会影响时间标记。
